# Пользователи

<hr>

## Возможности

<hr>

###	Подключена аутентификация пользователей из ЕСА
Для доступа пользователя из ЕСА в запрос должен быть включен заголовок с access-токеном от ЕСА:
```
Authorization: Bearer _токен от ЕСА_
```
#### Принцип работы
При запросе с токеном ЕСА, из токена получаем UUID пользователя и дату последнего обновления профиля.

Если у нас в базе нет пользователя с таким UUID, запрашиваем данные профиля у ЕСА и добавляем пользователя к себе в базу.

Если дата последнего обновления пользователя в нашей базе не совпадает с датой из токена, запрашиваем данные профиля у ЕСА и обновляем пользователя у себя в базе.

#### Ошибки
- Срок действия токена ЕСА истек  
  ```401 Token has expired```


- При декодировании токена ЕСА возникла ошибка  
  ```401 Invalid token```


- В токене ЕСА нет UUID пользователя  
  ```401 Token does not contain user_id```


- При получении данных профиля из ЕСА возникает ошибка подключенияК ЕСА  
  ```401 In ESA profile RequestException: {текст ошибки от ЕСА}```


- Данные профиля из ЕСА содержат не все нужные поля (имя, фамилия, телефон, почта, дата последнего обновления)  
  ```401 In ESA profile wrong fields```
 
<hr>

###	Подключена аутентификация для «своих» пользователей токену
Эта аутентификация подключена только для разработки (DEBUG=True).

Для доступа «своего» пользователя в запрос должен быть включен заголовок с токеном:  
```Authorization: Token _свой токен_```
 
#### Получение токена по логину/паролю тут:
```
POST http://127.0.0.1:8000/token-auth/
{
  "username": "string",
  "password": "string"
}
```

<hr>

###	Тип пользователя
При создании пользователя задается значение типа пользователя «Собственник» для любых пользователей (договоренность для MVP).

<hr>

###	QR-код для номера телефона
При создании пользователя или изменении номера телефона пользователя
создается и записывается в базу изображение с QR-кодом номера телефона.

(Посмотреть можно в эндпоинте "получение списка всех пользователей" или в админке.)  

<hr>

###	Изменения команды createsuperuser
Убран запрос почты при создании.

Добавлено автозаполнение обязательных полей модели (почта, телефон, имя, фамилия).

<hr>

###	Подключены эндпоинты
1. создание пользователя (create)
2. получение списка всех пользователей (list)
3. удаление пользователя (delete)
4. просмотр профиля пользователя (retrieve)
5. изменение профиля пользователя (put)
6. частичное изменение профиля пользователя (patch)

Эндпоинты 1-3 подключены только для разработки (DEBUG=True)
<br><br>
#### <u>Создание пользователя</u>
```
POST http://127.0.0.1:8000/users/dev/
```
Доступен для всех пользователей.

Пользователь создается только у себя в базе, НЕ отправляется в ЕСА.

При создании в `username` записывается `email`.
<br><br>
#### <u>Получение списка всех пользователей</u>
```
GET http://127.0.0.1:8000/users/dev/
```
Доступен только для superuser.
<br><br>
#### <u>Просмотр профиля пользователя</u>
```
GET http://127.0.0.1:8000/users/profile/
```
Доступен только авторизованным пользователям.
<br><br>
#### <u>Изменение профиля пользователя</u>
```
PUT http://127.0.0.1:8000/users/profile/
```
Доступен только авторизованным пользователям.
Для пользователя ЕСА меняется только аватарка (т.е. те поля, которых нет в ЕСА),
изменения в остальных полях будут игнорироваться.
Для "своего" пользователя меняются все доступные поля.
<br><br>
#### <u>Частичное изменение профиля пользователя</u>
```
PATCH http://127.0.0.1:8000/users/profile/
```
Доступен только авторизованным пользователям.
Для пользователя ЕСА можно поменять только аватарку (т.е. те поля, которых нет в ЕСА),
изменения в остальных полях будут игнорироваться.
Для "своего" пользователя меняются все доступные поля.
<br><br>
#### <u>Просмотр краткой информации о пользователе (для ЛК)</u>
```
GET http://127.0.0.1:8000/users/personal-account/
```
Доступен только авторизованным пользователям.
<br><br>
#### <u>Просмотр информации о наличии новых сообщений или уведомлений у пользователя</u>
```
GET http://127.0.0.1:8000/users/new-msgs/
```
Доступен только авторизованным пользователям.
<br><br>

###	Как работать с пользователем ЕСА
Swagger ЕСА тут:
```
http://api.dev.esa.ktsf.ru/api/v1/swagger-ui/
```
<br><br>
#### <u>Создание пользователя</u>
1. Создать пользователя  
```
POST http://api.dev.esa.ktsf.ru/api/v1/registration/
{
  "login":"str",
  "password":"str"
}
```
2. Получить токен для созданного пользователя
```
POST http://api.dev.esa.ktsf.ru/api/v1/auth/token/
{
  "login":" str",
  "password":"str"
}
```
3. Создать профиль пользователя
```
POST http://api.dev.esa.ktsf.ru/api/v1/registration/profile/
{
  "first_name": "string",
  "last_name": "string",
  "birthday": "2024-08-19T19:35:58.199Z",
  "phone": "string",
  "email": "user@example.com"
}
```
4. Обновить оба токена
```
POST http://api.dev.esa.ktsf.ru/api/v1/auth/token/
{
  "login":" str",
  "password":"str"
}
```
<br><br>
#### <u>Обновление access-токена по refresh-токену:</u>
```
POST http://api.dev.esa.ktsf.ru/api/v1/auth/token/refresh/
{
  "refresh": "string"
}
```
